# ADR 0003：scoutbadge 進度檔須先連接並登入 scoutbadge，才可匯出或匯入

- **日期**：2026-11-10
- **狀態**：已採納（Accepted）。取代 `AGENTS.md` §3 第 1 條及 `SCOPE.md`「獨立性原則」第 2 條原有的「獨立模式須保留本機／離線 JSON 交換」。

## 背景

1. **原有做法（v2.1.0 及以前）**：數位附錄同步卡的兩個檔案按鈕——匯出「待領袖核實」進度檔、匯入「領袖已核實」進度檔——任何時候都可用；封面歡迎頁的「匯入備份」亦會把 scoutbadge 進度檔直接匯入一本新紀錄冊。治理文件把這寫成獨立模式必須保留的能力。
2. **專案擁有人的要求（2026-11-10）**：SCOUTBOOK 要與姊妹倉 CUBSBOOK 同日的改動（PR #7）一致——未連接並登入 scoutbadge 前，不可匯出或匯入 scoutbadge 進度檔；連接表單自動讀取已登記旅團；找不到旅團時引導前往 scoutbadge 開戶。
3. **進度檔本來就以 scoutbadge 帳戶為前提**：匯出的申報檔帶有旅團編號，要交到該旅團的 scoutbadge 才有人核實；匯入的已核實檔由 scoutbadge 產生，並以 SCOUT ID 對應本人。完整紀錄冊備份則是 BOOK 自己的資料，與 scoutbadge 無關。

## 決策

1. **鎖定範圍只限 scoutbadge 進度檔**（已核實進度檔、「待領袖核實」申報檔）。未連接時，同步卡不顯示這兩個按鈕及檔案輸入框，原位改為鎖定提示。
2. **完整紀錄冊備份與還原不在鎖定範圍**：不需要網絡、不需要 scoutbadge，獨立模式下照常可用。BOOK「不接 scoutbadge 亦可完整使用」的原則不變。
3. **鎖定同時落在介面與處理函式**：`onExportFile`／`onImportFile` 本身先檢查登入狀態，不只靠隱藏按鈕；封面歡迎頁與選單不得另設可匯入進度檔的入口（測試鎖定 `importFromBadge`／`exportForBadge` 只可出現在同步卡）。
4. **「已連接」的定義**：本分頁的登入狀態同時具備 `token`、`ymis`、`troopId`（存於 `sessionStorage`）。殘缺的狀態一律當作未連接。
5. **旅團由清單選取**：連接表單的旅團欄讀取 scoutbadge 的已登記旅團清單（經伺服器端 `/api/scoutbadge`，零金鑰），並以 `upstreamOk` 分辨「沒有已登記旅團」與「暫時讀不到清單」；找不到旅團時顯示前往 scoutbadge 開戶的連結。

## 後果

- **正面**：與 CUBSBOOK 行為一致；進度檔只會在成員已有 scoutbadge 帳戶的情況下流通；旅團編號從清單選取，不會打錯或自行補零。
- **取捨**：
  - **沒有網絡（例如露營現場）或純靜態部署時，不能再以 JSON 檔與領袖交換進度。** 當面核簽請改用完全離線的 `SB1`／`SB1S.` 二維碼；進度檔要待有網絡並登入後才可匯出或匯入。
  - **登入狀態以分頁為準**：關閉分頁或瀏覽器後要重新登入，才可再匯出或匯入進度檔。
  - **這是流程上的閘門，不是安全邊界**：是否已連接只由前端按本分頁的登入狀態判斷，匯出或匯入當刻不會再向 scoutbadge 驗證 token；懂技術的用戶仍可自行製作同格式的 JSON。原有的把關不變——匯入會拒收「待領袖核實」申報檔及屬於另一位成員（SCOUT ID 不同）的進度，只錄入已核實項目；送往 scoutbadge 的一律是 `status: 'pending'`，要由領袖 CONFIRM。
  - **剛登記的旅團未必即時出現**：scoutbadge 的旅團清單要待其管理員登記並重新部署後才更新，回應亦設有邊緣快取。
  - CUBSBOOK 該次改動中的「家長連接頁」不適用：SCOUTBOOK 不設家長模式。
